# 知 · Chishiki

Личная библиотека заметок: редактируете Markdown в Obsidian, читаете на сайте.
Сайт и инструменты обслуживания работают на **TypeScript + Next.js + Node.js**.
Оформление написано обычными CSS и JavaScript; шрифты и браузерные ресурсы локальные.
Python для установки, запуска, проверки и обновления содержания не требуется.

Удаление прежнего стека и результаты проверок: [Session 035](reports/session035/README.md).

Грамматика английского, японского и корейского: [объяснения и применение в уроках 1–15](reports/session036/README.md) · [исправления прежних правил и ключей в уроках 1–5](reports/session037/README.md) · [уточнения шестого урока](reports/session038/README.md).

Языки: [активные словари, диалоги и самопроверка уроков 1–5](reports/session033/README.md).

Чтение и практика четырёх курсов: [уроки 11–15](reports/session032/README.md) · [уроки 6–10](LANGUAGES_SESSION030.md) · [уроки 1–5](LANGUAGES_SESSION029.md).

Программирование: [12 учебных глав и самостоятельная практика](PROGRAMMING_TEXTBOOK.md).

Учебная редакция: [как учиться по библиотеке](knowledge/overview/_contents.md) · [объём изменений и дальнейшие задачи](TEXTBOOK_PROGRESS.md).

## Локальный запуск

Нужны Node.js 22+ и pnpm 11.25.0. Установите зависимости из зафиксированного lockfile:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Откройте [http://localhost:5000](http://localhost:5000). Для production-запуска:

```powershell
pnpm typecheck
pnpm contents:verify
pnpm verify
pnpm build
pnpm start
```

По умолчанию сервер использует порт 5000. Команда `pnpm start` учитывает переменную `PORT`.
Подробности переноса и устройства приложения: [MIGRATION_NEXT.md](MIGRATION_NEXT.md).
Прежняя реализация Flask доступна в истории Git; её файлы и зависимости удалены из текущего стека.
Учебные заметки о Python остаются частью библиотеки.
Необязательные скрипты внутри хранилищ, например экспорт в Anki через `genanki`,
могут требовать Python для собственного запуска. Они не нужны сайту и обычному обслуживанию заметок.

## Как работать с заметками

Каталог и папки Obsidian используют структуру **раздел → уровень → урок → материалы**.
Например, `knowledge/languages/english/a1/unit-01/grammar/core.md`.
Папки показывают имеющиеся материалы и не означают полного покрытия уровня.
Общие материалы нескольких уровней находятся в `reference/`.
Подробнее: [STRUCTURE.md](STRUCTURE.md).

1. Откройте папку `knowledge/` как хранилище в Obsidian.
2. Создайте или отредактируйте `.md`-файл и сохраните его.
3. Обновите страницу локального сайта. Добавления, правки, переименования и удаления
   обнаруживаются при следующем сканировании; интервал сканирования — до 1,5 секунды.
4. Для удалённого сайта отправьте изменения в подключённую ветку и выполните новое развёртывание.

Сайт читает файлы, но не записывает изменения обратно в Obsidian.
Кэш приложения не синхронизирует файлы с Git или другим устройством.
На сервере с неизменяемым образом изменения заметок требуют нового развёртывания.

У разделов и уровней есть `_contents.md`. Обновление сначала показывает план изменений:

```powershell
pnpm contents:refresh
pnpm contents:refresh --apply
pnpm contents:verify
```

Первая команда ничего не записывает; `--apply` явно применяет изменения.
Страницы с frontmatter `editorial: manual` сохраняются без перезаписи.
Для нового раздела или уровня добавьте `_contents.md` в нужную папку.
Сайт обнаруживает новые папки и материалы независимо от обновления содержания.
Одноразовую реорганизацию папок повторно не выполняйте.

Внутренние ссылки: `[Заметка](../folder/note.md)` и `[Раздел](note.md#заголовок)`.
При отображении сайт преобразует их в адреса `/doc/...`.
Для переносимости используйте обычный Markdown: `[[Заметка]]`, Dataview и другие
расширения Obsidian на сайте не исполняются.

В `knowledge/` находятся **1348 Markdown-файлов**: 1217 исходных заметок и 131 страница содержания.
Сохранены обе коллекции: основная и вложенная `knowledge/knowledge/`.
Совпадающие материалы показываются с отдельными ссылками на версии; тексты не объединяются.
Карта `legacy_paths.json` содержит 1217 прежних путей. Она нужна приложению и развёртыванию;
перенаправления 308 сохраняют query-параметры, включая продолжение чтения.

## Поиск и чтение

- Поиск по названию, пути и полному тексту: Ctrl/Cmd K или `/`. Совпадения в названии имеют больший вес.
- Каталог поддерживает список, карточки и таблицу, сортировку и страницы по 24 заметки.
- Для внутренних ссылок доступна кнопка предпросмотра: название, отрывок и время чтения.
  Окно закрывается крестиком, Escape, нажатием снаружи или прокруткой.
- Связанные заметки учитывают исходящие и обратные ссылки, затем соседние материалы;
  подпись поясняет связь. Объединение одинаковых названий в этом блоке не меняет файлы.
- Шрифт, тема, вид каталога и история чтения сохраняются в браузере.
  История содержит до 20 заметок и позволяет продолжить чтение с места остановки.
  Между устройствами эти настройки не синхронизируются.
- На странице заметки доступны содержание, копирование ссылки и режим чтения.
  Таблицы и код прокручиваются по горизонтали на узких экранах.

При недоступном localStorage интерфейс продолжает работать, но настройки не сохраняются после перезагрузки.

## Развёртывание

`Dockerfile` собирает standalone-приложение на Node.js 22 и запускает `node server.js`
от непривилегированного пользователя. В образ входят заметки, карта старых адресов
и локальные ресурсы. База данных и постоянный диск приложению не нужны.

```sh
docker build -t chishiki .
docker run --rm -p 8000:8000 -e PORT=8000 chishiki
```

Проверьте [http://localhost:8000/healthz](http://localhost:8000/healthz) и главную страницу.
Для сервиса, который собирает репозиторий через Dockerfile, используйте корень репозитория,
маршрут проверки готовности `/healthz` и порт из `PORT`. Запуск уже задан в образе.
Настройки Railway и совместимость с GitHub Pages: [DEPLOYMENT.md](DEPLOYMENT.md).
Успешная локальная сборка не подтверждает выполнение Docker-контейнера или внешний деплой.

Публичный сайт показывает все включённые заметки; вход по паролю не реализован.
Сортировка по изменению использует время файлов, которое может меняться при сборке.

## Проверка и структура проекта

`pnpm verify` проверяет все документы, ссылки, фрагменты, HTML-якоря,
1217 целей старых адресов, иерархию и поиск. Отчёт сохраняется в `next-verification.json`.
Повторяющиеся названия между коллекциями фиксируются в отчёте и не означают потерю данных.
`pnpm contents:verify` отдельно проверяет обслуживание страниц содержания.

После изменений приложения также проверьте HTTP: `/`, `/api/search.json` с 1348 записями,
представительные `/doc/...`, неизвестный путь (404), старый адрес с query-параметрами (308),
поиск `/api/search` и предпросмотр `/api/preview/...`.

- `app/` — страницы Next.js и API.
- `components/` — общий интерфейс.
- `lib/knowledge.ts` — Markdown, ссылки, кэш, поиск и связанные заметки.
- `lib/catalog.ts` — разделы, уровни, уроки и версии обоих хранилищ.
- `public/static/` — актуальные CSS, JavaScript и локальные ресурсы.
- `scripts/` — инструменты TypeScript/JavaScript для запуска, содержания и проверок сайта.
- `knowledge/` — учебные материалы.
- `.agents/` — актуальные правила, состояние и журнал работы.

Старые редакторские отчёты описывают состояние на дату соответствующей сессии;
упоминания прежнего Python-инструментария в них являются историческими.
