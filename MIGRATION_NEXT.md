# Next.js / TypeScript

Переход одобрен пользователем 18 октября 2026 года. Сайт работает на Next.js App Router,
React и TypeScript; Markdown в `knowledge/` остаётся источником заметок для сайта и Obsidian.
Python-стек приложения и прежние скрипты обслуживания удалены из текущей версии.
Для установки, запуска, проверки и обновления содержания нужен Node.js, без Python.
Прежнюю реализацию можно посмотреть в истории Git. Учебный курс Python сохранён.
Необязательные примеры и вспомогательные скрипты внутри хранилищ, включая экспорт
в Anki через `genanki`, могут использовать Python отдельно от приложения.

## Запуск

Нужны Node.js 22+ и pnpm 11.25.0:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Адрес: [http://localhost:5000](http://localhost:5000). Production:

```powershell
pnpm typecheck
pnpm contents:verify
pnpm verify
pnpm build
pnpm start
```

`PORT` меняет порт production-сервера; `pnpm exec next dev --port 5001` запускает разработку
на другом порту. В Docker используется standalone-сборка Node.js; healthcheck — `/healthz`.
Выполнение Docker и внешний хостинг проверяются отдельно от локальной production-сборки.

## Устройство

- `app/`: React-страницы, layout, API поиска и предпросмотра.
- `components/shell.tsx`: общий интерфейс и навигация.
- `lib/knowledge.ts`: gray-matter, Markdown-it, highlight.js, ссылки, содержание,
  кэш по mtime/size, полнотекстовый поиск и связанные заметки.
- `lib/catalog.ts`: разделы, уровни, уроки, порядок материалов и версии из обоих хранилищ.
- `public/static/`: актуальные локальные CSS/JS. Шрифты и скрипты не требуют CDN.
- `legacy_paths.json`: 1217 постоянных перенаправлений 308 с сохранением query-параметров.
- `scripts/verify-next.ts`: аудит 1348 документов, ссылок, якорей, идентификаторов,
  прежних адресов, иерархии и поиска. Отчёт — `next-verification.json`.
- `scripts/refresh-contents.ts`: обслуживание `_contents.md`, сначала без записи;
  `scripts/verify-contents.ts` проверяет этот инструмент и его ограничения.

Обычные HTML-ссылки выполняют полную навигацию. Ключи localStorage темы, вида каталога,
шрифта и истории чтения сохранены. Добавления, изменения и удаления Markdown обнаруживаются
при следующем запросе; интервал сканирования — до 1,5 секунды. Кэш хранит разобранные файлы
и повторно обрабатывает изменённые. На хостинге с неизменяемым образом нужна новая публикация.

Полнотекстовый поиск и обработка Markdown выполняются на сервере Node.js.
Приложение требует серверного запуска и не использует статический экспорт.
Первое обращение прогревает кэш; скорость зависит от окружения и объёма заметок.

Настройки Railway, команды запуска и ограничения GitHub Pages описаны в
[DEPLOYMENT.md](DEPLOYMENT.md). Текущий вариант подходит для Node.js-хостинга;
для GitHub Pages требуется отдельная статическая адаптация.

## Обновление содержания

```powershell
pnpm contents:refresh
pnpm contents:refresh --apply
pnpm contents:verify
```

Без `--apply` выводится только план изменений. Ручные страницы с `editorial: manual`
не перезаписываются. Для нового раздела сначала создайте `_contents.md` в нужной папке.
Одноразовую реорганизацию папок повторно не выполняйте; карта прежних путей сохраняется.

## Сохранность материалов

Сохранены 1217 исходных заметок и 131 страница содержания, всего 1348 файлов.
Оба хранилища остаются отдельными версиями. Относительные `.md`-ссылки, старые якоря
и параметры продолжения чтения нужно сохранять при дальнейшем редактировании.

Markdown-it обрабатывает таблицы, HTML и блоки кода. После изменений парсера проверяйте
их отображение и полный аудит ссылок; особенности старого парсера не гарантируют
тождественное отображение каждого расширения. Исторические отчёты о миграции и редактуре
сохраняют результаты на дату сессии. Актуальные ограничения и задачи находятся
в `.agents/STATE.json` и последних редакторских отчётах.
