# Топ книг по программированию

Книги, которые стоит прочитать каждому разработчику. Сгруппированы по темам.

---

## 1. Чистый код и архитектура

### Clean Code — Роберт Мартин (2008)

**О чем:** Как писать чистый, читаемый, поддерживаемый код. Примеры на Java.

**Ключевые идеи:**
- Имена должны раскрывать намерение
- Функции должны быть маленькими (10–20 строк)
- Комментарии — зло, код должен объяснять себя сам
- Дублирование — корень всех зол (DRY)
- Структура: файлы классов → файлы зависимостей → система

**Для кого:** Начинающие и средние разработчики.

**Рекомендация:** Читать с карандашом — отмечать, что применимо к твоему коду.

### Clean Architecture — Роберт Мартин (2017)

**О чем:** Архитектура ПО: boundaries, use cases, dependency rule.

**Ключевые идеи:**
- Архитектура = границы между уровнями
- Dependency Rule: зависимости направлены внутрь
- Use cases определяют архитектуру
- Framework — деталь, а не основа

**Для кого:** Старшие разработчики, техлиды.

### The Pragmatic Programmer — David Thomas, Andrew Hunt (1999)

**О чем:** 99 советов для программистов: от DRY до «don't live with broken windows».

**Ключевые идеи:**
- DRY (Don't Repeat Yourself)
- Orthogonality (независимость компонентов)
- Tracer Bullets (быстрая обратная связь)
- Refactoring (постоянное улучшение)
- Don't Repeat Yourself — не только код, но и знания

**Для кого:** Все разработчики.

### Refactoring — Мартин Фаулер (1999, 2018)

**О чем:** Техники рефакторинга — улучшение структуры кода без изменения поведения.

**Ключевые идеи:**
- Мелкие шаги (code smell → рефакторинг → тесты)
- Каталог рефакторингов: Extract Method, Rename, Move...
- Рефакторинг как повседневная практика
- Второе издание (2018) — на JavaScript

**Для кого:** Все, кто работает с существующим кодом.

### Code Complete — Стив Макконнелл (2004)

**О чем:** Энциклопедия разработки ПО: от проектирования до тестирования.

**Для кого:** Справочник — не обязательно читать от корки до корки.

## 2. Алгоритмы и структуры данных

### Грокаем алгоритмы — Адитья Бхаргава (2016)

**О чем:** Визуальное введение в алгоритмы: бинарный поиск, сортировки, графы, динамическое программирование.

**Ключевые идеи:**
- Big-O: O(log n) vs O(n) vs O(n²)
- Бинарный поиск — основа оптимизации
- Рекурсия → итерация → динамическое программирование
- Графы: BFS, DFS, алгоритм Дейкстры

**Для кого:** Начинающие. Отличная книга для входа в алгоритмы.

**Рекомендация:** Решать задачи параллельно (LeetCode, HackerRank).

### Introduction to Algorithms (CLRS) — Cormen, Leiserson, Rivest, Stein (1990, 2022)

**О чем:** Полный учебник по алгоритмам: сортировки, графы, DP, NP-полнота.

**Ключевые идеи:**
- Математический подход к алгоритмам
- Divide and Conquer
- Greedy algorithms
- Dynamic programming
- Амортизированный анализ

**Для кого:** Студенты, серьёзные разработчики.

**Рекомендация:** Не для чтения подряд — как справочник.

### The Algorithm Design Manual — Steven Skiena (2008)

**О чем:** Практический подход к алгоритмам + «war stories» из реальной жизни.

**Ключевые идеи:**
- Алгоритмы в контексте реальных задач
- War stories: как применялись алгоритмы
- Каталог проблем и подходов к ним

**Для кого:** Разработчики, которые хотят понять, как применять алгоритмы.

### Algorithms — Robert Sedgewick, Kevin Wayne (2011)

**О чем:** Алгоритмы с акцентом на реализации на Java.

**Ключевые идеи:**
- Практические реализации
- Визуализации на algorithms.org
- Сортировки, деревья, графы, строковые алгоритмы

**Для кого:** Те, кто хочет видеть рабочий код алгоритмов.

## 3. Паттерны проектирования

### Design Patterns — «Банда четырёх» (1994)

**О чем:** 23 паттерна проектирования для ООП.

**Ключевые идеи:**

| Категория | Паттерны |
|-----------|----------|
| Порождающие | Factory, Abstract Factory, Builder, Singleton |
| Структурные | Adapter, Decorator, Proxy, Facade |
| Поведенческие | Observer, Strategy, Command, Iterator |

**Для кого:** Все, кто работает с ООП.

**Рекомендация:** Не заучивать, а понимать паттерны и когда их применять.

### Head First Design Patterns — Eric Freeman (2004)

**О чем:** Те же паттерны, но в формате Head First (визуально, с примерами).

**Для кого:** Начинающие, кому сложно читать академические книги.

## 4. Проектирование систем

### Designing Data-Intensive Applications (DDIA) — Мартин Клеппман (2017)

**О чем:** Как работают распределённые системы, базы данных, потоки данных.

**Ключевые идеи:**
- Репликация, шардинг, партиционирование
- ACID vs BASE
- Потоки данных (Kafka, event sourcing)
- Консистентность vs доступность (CAP theorem)

**Для кого:** Бэкенд-разработчики, архитекторы, DevOps.

**Рекомендация:** Одна из самых важных книг для backend-разработчика.

### System Design Interview — Alex Xu (2020)

**О чем:** Как проектировать системы на собеседованиях.

**Ключевые идеи:**
- Шаги проектирования: требования → архитектура → компоненты
- Case studies: URL shortener, news feed, chat
- Масштабирование: горизонтальное vs вертикальное

**Для кого:** Те, кто готовится к собеседованиям.

### Building Microservices — Sam Newman (2015)

**О чем:** Микросервисы: паттерни, антипаттерны, инструменты.

**Для кого:** Разработчики, работающие с микросервисами.

## 5. Языки программирования

### The C Programming Language (K&R) — Kernighan, Ritchie (1978)

**О чем:** Библия языка C.

**Для кого:** Все, кто хочет понимать низкоуровневое программирование.

### Structure and Interpretation of Computer Programs (SICP) — Abelson, Sussman (1984)

**О чем:** Программирование как способ выражения идей (на Scheme).

**Для кого:** Те, кто хочет глубокого понимания абстракций.

### Effective Java — Joshua Bloch (2008, 2018)

**О чем:** 90 советов по эффективному использованию Java.

**Для кого:** Java-разработчики.

### The Rust Programming Language — Steve Klabnik, Carol Nichols (2019)

**О чем:** Полное введение в Rust: ownership, borrowing, lifetimes.

**Для кого:** Те, кто изучает Rust.

## 6. Тестирование и качество

### Working Effectively with Legacy Code — Майкл Физ (2004)

**О чем:** Как работать со старым кодом и делать его лучше.

**Для кого:** Все, кто работает с существующим кодом (т.е. все).

### Test Driven Development — Kent Beck (2002)

**О чем:** TDD: красный-зелёный-рефакторинг.

**Для кого:** Те, кто хочет писать надёжный код.

### xUnit Test Patterns — Gerard Meszaros (2007)

**О чем:** Паттерны тестирования: unit, integration, acceptance.

**Для кого:** Тестировщики и разработчики.

---

## 7. DevOps и инфраструктура

### The Phoenix Project — Gene Kim (2013)

**О чем:** Роман о DevOps: как IT спасает компанию.

**Для кого:** DevOps, менеджеры, разработчики.

### Site Reliability Engineering — Google (2016)

**О чем:** Как Google обеспечивает надёжность систем.

**Для кого:** SRE, DevOps.

### Docker Deep Dive — Nigel Poulton (2018)

**О чем:** Полное руководство по Docker.

**Для кого:** Все, кто работает с контейнерами.

## 8. Мягкие навыки

### Peopleware — Tom DeMarco, Timothy Lister (1987)

**О чем:** Управление командами, офисная среда, культура.

**Для кого:** Техлиды, менеджеры.

### The Mythical Man-Month — Fred Brooks (1975)

**О чем:** «Добавление людей к просроченному проекту делает его ещё больше».

**Для кого:** Все, кто работает в команде.

### Death March — Edward Yourdon (1997)

**О чем:** Как выживать в проектах «смертельного марафона».

**Для кого:** Разработчики в сложных проектах.

## Рекомендации по чтению

### Начинающим (первые 6 месяцев)
1. Грокаем алгоритмы
2. Clean Code
3. The Pragmatic Programmer

### Средним (1–3 года)
1. Design Patterns
2. DDIA
3. Refactoring

### Продвинутым (3+ лет)
1. CLRS (как справочник)
2. Clean Architecture
3. SICP

### Для собеседований
1. System Design Interview
2. Грокаем алгоритмы (повторить)
3. CLRS (для теории)
