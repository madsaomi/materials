Каждое из 12 учебных ядер содержит предпосылки, инструкцию запуска, конкретную модель, цельный пример с проверками и объяснение шагов. Рядом — самостоятельная задача с отдельным раскрываемым решением, пояснение выбора, границы применимости и новое требование для переноса навыка.

Не каждый пример печатает результат: проверки `assert`, `assert_eq!` и проверки с исключением обычно завершаются молча при успехе. Ошибка проверки прерывает запуск. В Go-примерах с `fmt.Println` дополнительно выводится число.

В Python-уроке 3 решение задачи продолжает класс Cart из теории; сначала выполните определение класса. Остальные новые решения запускаются отдельными файлами. Go и Rust содержат полноценные программы: не объединяйте два `main` в одном файле.

## Организация

- 12 теоретических глав дополнены учебным ядром; прежний материал остаётся ниже как подробный справочник.
- 12 практикумов дополнены самостоятельными заданиями. Прежние задачи и разобранные проекты доступны в отдельном раскрываемом банке решений.
- 4 содержания языков получили последовательный маршрут и защищены от автоматической генерации через `editorial: manual`.
- 23 остальные страницы содержаний программирования получили подходящий маршрут вместо языковой инструкции.
- Каталог сайта и вспомогательный генератор содержаний теперь ставят `syntax` перед `practice`. Проверка покрывает все 12 папок уроков.

Программы и резервные копии находятся вне репозитория, в папке результатов этой беседы `programming-before-session028`. Проверку можно повторить:

```text

```

Для Go/Rust задайте `LESSON_GO` и `LESSON_RUSTC` путями к компиляторам; для Python при необходимости задайте `LESSON_PYTHON`. Go-примеры используют стандартную библиотеку и `%w` (Go 1.13+); для курса предпочтителен установленный поддерживаемый выпуск. Rust-примеры рассчитаны на stable.

Одноразовые скрипты `improve-programming.ts` и `programming-navigation.ts` повторно не запускать поверх текущих файлов.

## Ограничения и продолжение

Учебные ядра проверены отдельно от большого прежнего справочника. Их добавление не означает проверки каждого старого проекта, версии API или готового решения. Для следующих редакций нужны самостоятельные задания по оставшимся темам глав, предметная проверка старого кода и полноценные проекты с критериями приёмки.

Другие предметные разделы и незавершённые китайские словарные записи остаются отдельными задачами. Этап языковой редакции описан в [TEXTBOOK_PROGRESS.md](TEXTBOOK_PROGRESS.md).
